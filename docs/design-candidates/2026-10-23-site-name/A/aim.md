# 狙い

## 狙い

- サイトの名前を **works** にし、本名を表紙の大きな見出しから外す。「作ったもの（works）」を置く場所という意味で、一言「作ったアプリや道具と、書いた記事を置いています。」とそのままつながる。リポジトリ名・Vercel のプロジェクト名（`n-yoshida-works`）とも同じ語で、URL・リポジトリ・表紙の名前が一致する
- 持ち主は、名前の 1 行上に GitHub のハンドル名を **`n-yoshida-dev /`** と等幅・薄い文字で前置して示す。GitHub のリポジトリの題名「owner / repo」と同じ読み方なので、GitHub から来た人にはそのまま伝わり、本名を大きく出さずに「誰のサイトか」が表紙だけで分かる
- 表紙の骨組み（PC は左に名前と一言・右に目次、スマホは縦並び・目次 2 列、線だけの区切り、開いたときの動き）は今のまま変えない。変えたのは「名前」の枠の中身だけなので、CSS の差分が小さく、見た目の決まり（DESIGN.md）にも触れない

## 節ごとの工夫

1. **サイトの名前**：`works`。表紙では `n-yoshida-dev / works`（ハンドル名を小さく前置）、タブの題名と `og:site_name` は 1 語につなげた `n-yoshida-dev/works`（他のページは今の形のまま「ページ名 — n-yoshida-dev/works」）。OG 画像は名前の行を「n-yoshida-dev /」「works」の 2 行に差し替えるだけで、色と配置は今のまま。本名はフッターの著作権表示「© 2026 Naoki Yoshida」に残す（`SITE.name` とは別の定数に分ける想定。未確認）
   - 代わりの候補と、選ばなかった理由：
     - `n-yoshida-dev` だけ：GitHub・Qiita と同じ文字列で迷いがないが、題名というよりユーザー名に見え、「何のサイトか」が名前から分からない
     - `Naoki Yoshida / works`：持ち主を本名で前置する形。読み方は同じだが、本名が再び表紙の最初の行に出るので、気恥ずかしさの元が残る。本名を出したい場合はこちらに差し替えても表紙の骨組みは変わらない
     - 造語の名前（屋号のような固有の語）：覚えやすさはあるが、GitHub・Qiita・URL のどれとも結びつかず、名前の説明が要る。今のサイトは「作ったものを置く場所」以上の意味を持たないので、見送った
2. **表紙の見せ方**：名前の枠を「持ち主（等幅・薄い文字・1 行目） → サイトの名前（大きな見出し） → 一言」の 3 段にした。見出しは小文字の `works` 1 語なので、本名のときより横に短く、PC ではその分の余白が左の列に残り、右の目次とつり合う。スマホでは 1 行に収まり、本名のときの 2 行折れの心配がない。ハンドル名はリンク（GitHub へ）にしてあるが、色は薄い文字色のままにして、青はリンクカードと目次だけに残した。開いたときの動きは、持ち主の行を見出しと同じタイミングで浮かせる
