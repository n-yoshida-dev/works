# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

ここに書くのは**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）。
Claude が実装中に選んだ技術的な選択とハマりどころは `KNOWLEDGE.md`。やることは `TODO.md`。
追記は `/decide`。新しいエントリは下の `---` の直後に入れる（`/decide` がそうする）。

**このリポジトリは公開する前提なので、ユーザーの発言の原文は写さず要旨にとどめる。** 原文と計画の全体は ops に記録。

前身のサイトの判断台帳（手元の `../portfolio/logs/decisions.md`）のうち、見た目・カードの形・Ask AI の言葉・バイブコーディングの備考・禁止語スキャンに許可リストを作らない、などの決定は引き継ぐ。
コードのコメントにある「logs/decisions.md 2026-10-xx」はそこを指している。T12 で、引き継ぐものを要約してここに移す。

1 エントリの形式（`/decide` と同じ。1 エントリ 1 判断）：

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）
```

## 2026-10-20 `/articles` を `/writing` に改名する

**論点**: ナビの名前を Writing にするとき、URL も変えるか
**結論**: 変える。URL は `/writing`、Markdown 版は `/writing.md`（T7）
**理由**: ナビの名前と URL を揃える。新しいサイトなので古い URL を守る必要が無い
**却下した代替案**: URL は `/articles` のまま、ナビだけ Writing（名前と URL がずれる）
**確信度**: 中
**見直す条件**: なし

## 2026-10-20 About の一言から仕事の年数を外す

**論点**: トップの名前の下の一言に何を書くか
**結論**: 仕事の年数や職種の説明を外し、作っているものを書く（仮の文：「生活や学習で使うツールと、AI と開発する仕組みを作っています。」。文案は T8 で本人が読む）
**理由**: このサイトはキャリアの情報を載せない
**却下した代替案**: 前身の一言のまま
**確信度**: 高
**見直す条件**: なし

## 2026-10-20 Ask AI を残す

**論点**: 訪問者の AI にサイトを読ませる Ask AI を、新しいサイトにも置くか
**結論**: 残し、依頼文を「作品・道具・記事を紹介する」形に直す（T8）
**理由**: AI 向けの入口（llms.txt・Markdown 版）と合わせて、このサイトの特徴になっている
**却下した代替案**: 節ごと消す（後から足すのは簡単だが、今ある物を捨てる理由が無い）
**確信度**: 中
**見直す条件**: 3 つの AI で試して、キャリアの情報を推測で答えるのを止められないとき

## 2026-10-20 Systems を独立した節として残す

**論点**: 開発・学習・読書の仕組み（Systems）を、Projects に混ぜるか分けるか
**結論**: 分けたまま残す
**理由**: Projects は使うもの、Tools は入れるもの、Systems は読むもので、読み手の行動が違う。4 本は本文まで完成している
**却下した代替案**: Projects に `kind: system` で混ぜる（ナビは 1 つ減るが、カードの一覧に長い読み物が混ざる）
**確信度**: 中
**見直す条件**: なし

## 2026-10-20 名前は works / n-yoshida-works

**論点**: 新しいリポジトリと Vercel のプロジェクトの名前
**結論**: GitHub は `works`、Vercel は `n-yoshida-works`（URL は `n-yoshida-works.vercel.app` の見込み）。サイト名（タブ・OGP）は「Naoki Yoshida」のまま
**理由**: 短く、「作ったもの」そのもの。`works.vercel.app` は他人が使っている
**却下した代替案**: `builds`
**確信度**: 中
**見直す条件**: Vercel で名前が取れないとき（Vercel が乱数を足す）

## 2026-10-20 作ったものだけのサイトを、新しいリポジトリで履歴なしから作る

**論点**: 作ったものとキャリアの情報が同居する前身のサイトを、どう分けるか
**結論**: 作ったものだけを載せるこのリポジトリを `git init` 相当から作り、前身からは必要なファイルだけを写す。前身は非公開の保存用にする。キャリアの情報は別の非公開の置き場に移す（ここからはリンクしない）
**理由**: 前身を公開のまま直しても、消した内容が Git の履歴に残る。新しく作れば履歴に持ち込まない
**却下した代替案**: 前身を公開のまま改修する（履歴の書き換えが要り、それでも外部のキャッシュは消せない）
**確信度**: 高
**見直す条件**: なし
