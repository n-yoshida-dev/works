# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

ここに書くのは**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）。
Claude が実装中に選んだ技術的な選択とハマりどころは `KNOWLEDGE.md`。やることは `TODO.md`。
追記は `/decide`。新しいエントリは下の `---` の直後に入れる（`/decide` がそうする）。

**このリポジトリは公開する前提なので、ユーザーの発言の原文は写さず要旨にとどめる。** 原文と計画の全体は ops に記録。

前身のサイトの判断台帳（手元の `../portfolio/logs/decisions.md`）のうち、見た目・カードの形・Ask AI の言葉・バイブコーディングの備考・禁止語スキャンに許可リストを作らない、などの決定は引き継ぐ。
コードのコメントにある「logs/decisions.md 2026-10-xx」はそこを指している。T12 で、引き継ぐものを要約してここに移す。

1 エントリの形式（`/decide` と同じ。1 エントリ 1 判断）：

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）
```

## 2026-10-23 サイトの名前を works にし、持ち主は名前の下に小さく添える

**論点**: 本名「Naoki Yoshida」がサイトの題名として表紙に大きく出ていることへの、本人の気恥ずかしさ（本名を隠したいわけではない）。もっと良い名前があるか
**結論**: サイトの名前（表紙の見出し・タブ・OGP・OG 画像・左の目次・llms.txt の見出し）は「works」。表紙では名前の下に小さく「Naoki Yoshida / n-yoshida-dev」と添える（GitHub や Qiita のアカウント名を書くように）。本名はフッターの著作権表示と AI への依頼文に持ち主として残す。開いたときの動きは今の表紙のもの（コンペの C）
**理由**: 本人がコンペ（`docs/design-candidates/2026-10-23-site-name/`）の 3 案を見て、B の組み方から上の姓を外し、署名にアカウント名を足す形に組み替えた（本人の言葉の原文は ops に記録）
**却下した代替案**: 本名のまま（気恥ずかしさが残る）。「n-yoshida-dev / works」（A・C。審査役 1 のおすすめ）。「Yoshida Works」（B。審査役 2 のおすすめ）
**確信度**: 中
**見直す条件**: なし（2026-10-20「名前は works / n-yoshida-works」のサイト名の部分は、この決定で置き換えた）

## 2026-10-22 表紙の要点 3 行をやめ、各節の見出しの下に「これは何か」を 1 行置く

**論点**: 表紙の要点 3 行（作っているもの・開発の道具・書いているもの）の文章量
**結論**: 要点 3 行は表紙から外す。代わりにトップの Projects / Tools / Systems の見出しのすぐ下に「これは何か」の 1 行を置く。Writing の 1 行には本数・連載の数を入れない（数は見出しの件数と図が持つ）
**理由**: 本人が、要点は文章量が多く要らず、各見出しの下に軽い説明を入れるほうがよいと判断した。本数は変わっていくので文に入れない（2026-10-23）
**却下した代替案**: 要点 3 行を短くして残す
**確信度**: 高
**見直す条件**: なし

## 2026-10-22 「このサイトに無いもの」をわざわざ書かない

**論点**: キャリアの情報が無いことを、本文・Ask AI の依頼文・llms.txt に明記して、AI の推測を止めるか
**結論**: 書かない。無ければよい
**理由**: 本人の判断。載せていないものを、わざわざ書く必要は無い
**却下した代替案**: 「仕事の内容や技術の評価は載せていない」「推測で答えない」を足す（Claude の T8 の初案）
**確信度**: 高
**見直す条件**: 本番で 3 つの AI に Ask AI を試し、キャリアの情報を推測で答えたとき（2026-10-20「Ask AI を残す」の見直す条件と同じ）

## 2026-10-20 作ったものだけのサイトを、新しいリポジトリで履歴なしから作る

**論点**: 作ったものとキャリアの情報が同居する前身のサイトを、どう分けるか
**結論**: 作ったものだけを載せるこのリポジトリを `git init` 相当から作り、前身からは必要なファイルだけを写す。前身は非公開の保存用にする。キャリアの情報は別の非公開の置き場に移す（ここからはリンクしない）
**理由**: 前身を公開のまま直しても、消した内容が Git の履歴に残る。新しく作れば履歴に持ち込まない
**却下した代替案**: 前身を公開のまま改修する（履歴の書き換えが要り、それでも外部のキャッシュは消せない）
**確信度**: 高
**見直す条件**: なし
